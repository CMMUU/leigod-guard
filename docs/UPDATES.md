# 自动更新规则

本规则适用于 0.10.0 及后续版本。入口为「关于与更新」→「更新来源」。

## 来源选择

| 模式 | 检查与下载行为 |
| --- | --- |
| 自动选择（国内优先），默认 | 同时检查 Gitee 和 GitHub，选择可用的正式新版本；版本相同优先 Gitee，下载失败尝试备用源 |
| 仅 Gitee（国内） | 版本、校验文件、程序包均只访问 Gitee；失败时保留重试和手动下载入口 |
| 仅 GitHub | 版本、校验文件、程序包均只访问 GitHub；失败时保留重试和手动下载入口 |

版本号优先于来源优先级。例如当前为 0.8.0、Gitee 为 0.9.0、GitHub 为 0.10.0 时，选择 GitHub 的 0.10.0；两边都是 0.10.0 时优先 Gitee。某一来源不可访问时，仍可使用另一来源的完整新版本，但会注明未能完成全部来源检查。可访问来源没有更高版本、另一来源失败时，只显示检查不完整，不宣称已是最新版。

只接受严格的 `v主版本.次版本.修订版本` 正式版本及完整发布资产：安装 EXE、绿色 ZIP、`SHA256SUMS.txt`。不安装预发布、草稿、低于或等于当前版本的内容。Gitee 比较最近 100 条公开发布的版本号；GitHub 使用本仓库的正式最新版接口。资产不完整或元数据异常的来源视为检查失败。

新配置、缺少 `updates.source` 的配置采用 `auto`。已有配置保存的 `github` / `gitee` 保留为相应单源模式；升级后如需自动优选，请手动选一次「自动选择（国内优先）」。切换选项清除旧检查结果，需重新检查；正在检查或下载时不能切换来源。

## 下载与备用源

用户点击「下载并更新」时固定目标版本和当前安装方式。主来源下载失败，自动模式最多尝试一次备用来源；若尚未取得备用信息，只查询原目标标签，不重新选择另一个最新版。

备用文件必须与主文件的版本、安装方式、精确文件名及大小一致，并满足已经确认的 SHA-256。已取得 GitHub 资产摘要时，也用它约束 Gitee 文件。尚未开始下载且还未取得任何摘要时，备用源可建立初始校验值；一旦有校验值就不能在切换时替换它。每个来源的文件仍与其发布校验表核对，下载结束重新核对完整大小与 SHA-256。

失败的临时文件会关闭并删除，切换来源从头下载，不跨来源拼接或续写残片。同版本未同步、元数据或校验值不一致时停止更新；不得为了完成下载而降级或换装其他版本。界面显示当前尝试来源，切换时重置进度。

版本检查在后台并行进行，共用 8 秒请求期限；建立连接最多等待 5 秒。校验文件请求限时 30 秒。程序包等待响应或单次读取无数据的超时为 30 秒，持续有进度的慢速下载不会因此被截断；每个来源的传输循环上限为 10 分钟，检查边界可能另包含最后一次读取的等待。最多主来源和备用来源各尝试一次，不做反复测速或无限重试。

请求均匿名且只访问固定的项目地址与允许的官方分发域名，不发送雷神账户凭据。SHA-256 验证文件完整性，不能替代独立代码签名。

## 安装与发布

「启动时自动检查更新」保持默认关闭；开启后也只检查，必须点击「下载并更新」才下载及安装。安装版继续用安装 EXE，绿色版继续用 ZIP；更新保留原配置。更新期间监控短暂停止，重新打开后执行正常启动策略，详见 [README](../README.md#应用内更新)。

GitHub 是主发布源，Gitee 同步完全相同的文件。同步依赖维护者在 GitHub Actions 配置 `GITEE_TOKEN`，并验证同步成功；用户下载无需令牌。GitHub 发布成功、Git 分支同步成功，都不能代替 Gitee Release 及附件已经就绪的确认。参见 [发版约定](RELEASING.md#自动同步到-gitee)。

修改更新器时至少验证：同版国内优先、不同版本选新、来源离线与检查不完整、单源隔离、固定版本回退、安装方式保持、错误大小和哈希拒绝、连续慢速下载与停滞超时、旧配置兼容。安装和恢复测试继续在隔离 runner 执行。
