# 多用户远程守护与 Web 页面规划

方案日期：2026-09-19。状态：用户已确认采用 Tabler 统一用户侧和管理侧；已制作[三页视觉稿](remote-guard-design/README.md)，待评审，尚未开发或部署服务器功能。桌面守护先修补正常关机的通知处理；现有官网继续负责项目介绍和下载。下述域名、时间和容量都是建议，不代表已经配置或验证。

## 范围与账号边界

- 保留无需平台注册的本地守护。只有主动开启远程兜底的用户才需要平台账号、设备配对和雷神账号绑定。
- 平台账号与雷神账号分开：前者用于登录守护网站、管理设备；后者的授权凭据仅用于用户授权的查询/暂停。网站登录不等于雷神登录有效，更不等于设备在线。
- 一个用户可管理多台电脑；数据表/API/后台任务均以所属用户约束访问。用户不能查看、绑定或操作其他用户的数据，管理员权限由后端验证，不能只隐藏菜单。
- 一个雷神账号关联多台电脑时，决策按该账号汇总；任一有效的游戏/准备游戏保护会话仍在使用，就不因其他设备离线而暂停。相同雷神账号跨平台用户重复绑定应拒绝或走明确的转移/共享授权流程，不能形成两套互不知情的暂停策略。
- 用户角色用于自己的状态与操作；管理员角色看总体使用、设备、失败与审计。管理员不展示原始雷神 token、密码或完整凭据，不提供默认批量暂停全部账号的入口。

## 用户页面

首版只需两个主要页面，手机浏览器也应可用。

### 登录 / 注册 / 找回密码

统一登录页，建议邮箱与密码，注册和密码找回作为同一布局中的流程。邮箱验证码需要邮件服务后才能上线，不能使用演示验证码或前端假登录。管理员建议额外启用二次验证。

登录采用后端验证、密码单向安全哈希、可撤销会话及安全 Cookie；对登录和找回操作限流。前端页面与后端同域部署可减少跨域会话复杂度。具体认证实现随技术选型确定。

### 我的守护 / 状态页

- 顶部：远程保护开关、保护状态、最近更新时间；尚未授权时明确“未启用”，不能显示绿色“受保护”。
- 账号卡片：脱敏账号、雷神登录是否有效、最近查询的计时状态、剩余时长（时/分/秒）、查询时间。查询失败保留旧值并标注过期，不把旧数据当实时数据。
- 设备列表：设备名、在线/离线/未知、客户端版本、最近心跳、名单游戏是否运行、准备游戏保护剩余时间。
- 操作：配对新设备、撤销设备、远程兜底开关、准备游戏延后、立即请求暂停、刷新状态。操作结果区分“请求已接受”“暂停已确认”“暂停未确认”。
- 最近事件：本地暂停、失联开始、延迟检查、远程请求、查询确认、授权失效；展示操作者与触发来源。
- 简单趋势：近 7 天已确认暂停次数、设备在线时段。不能把无法证明的“节省时长/节省金额”作为真实指标。

## 管理页面与图表口径

管理入口可使用 `/admin`，与用户侧共享组件和配色，内容权限完全由服务器控制。

| 指标 | 统计口径 | 展示方式 |
| --- | --- | --- |
| 注册用户数 | 平台未删除用户总数；停用数单独列出 | 数字卡片 |
| 登录活跃用户数 | 最近 5 分钟有已认证网页活动的去重用户；有效登录会话数另列 | 数字卡片 + 24 小时折线 |
| 客户端在线用户数 | 至少有一台有效心跳设备的去重用户 | 数字卡片 + 折线 |
| 在线设备数 | 最近 45 秒收到有效心跳的设备，超时再按兜底阈值处理 | 数字卡片 + 在线/等待/离线堆叠图 |
| 远程保护启用数 | 已授权并开启远程策略的雷神账号；凭据未知/失效单独标注 | 状态分布 |
| 远程暂停结果 | 按唯一任务统计成功确认、失败、未确认、取消，不将重试当新任务 | 每日堆叠柱状图 |
| 暂停确认率 | 查询确认暂停的任务数 / 已发送暂停请求的任务数；同时展示分母和未确认数 | 趋势折线 + 比例 |
| 处理延迟 | 从失联阈值触发到结果确认的时间，保留失败/未完成分类 | P50/P95 趋势 |
| 失败原因 | 登录失效、请求超时、接口拒绝、服务不可用等脱敏类别 | 横向条形图 + 明细 |
| 系统健康 | 待处理任务数、到期任务积压、API 错误率、最近调度时间 | 卡片 + 趋势 |

登录会话、网页在线、客户端在线、雷神登录有效是四种不同状态。未知应单独计数。管理员用户表支持按状态筛选、查看设备和审计记录；界面轮询可先采用 10～15 秒，标出数据时间，后续再考虑 SSE。所有脚本、字体与图表资源随站点部署，避免依赖境外 CDN 才能显示。

## 远程兜底流程

1. 用户登录平台并显式开启远程兜底，通过一次性短时配对码连接桌面设备。设备使用独立、可撤销的设备凭据，不使用用户网页登录 Cookie 报心跳。
2. 客户端建议每 15 秒发送最小必要状态：设备会话代次、游戏是否运行、保护截止时间、版本。服务器使用自己的接收时间；不上传完整进程列表。
3. 正常关机本机立即暂停，并尽力发送带会话代次的关机通知。远端不依赖该通知必达；本地成功后可更新状态。
4. 建议连续 120 秒没有心跳才启动失联暂停判断，并复核同一雷神账号的全部设备、准备游戏期限、用户授权及已知计时状态。失联不等于已经关机，阈值可以调整。
5. 对雷神账号串行处理任务；任务绑定设备会话代次和策略版本，执行前复核最新状态。恢复在线、延后保护、关闭远程功能、撤销授权时取消尚未发送的旧任务。在请求已发出后的竞态不能靠前端隐藏；需要记录结果并明确暂停边界，不自动恢复计时。
6. 暂停接口返回成功后再查询计时状态；失败有限重试并退避，凭据失效停止重试并提醒重新授权。后台重启不能丢失待执行任务，也不能在积压恢复时直接执行未经复核的旧任务。
7. 服务自身异常或大量设备同时失联时进入告警/保守模式，避免因守护服务器网络故障而集中误暂停。具体阈值通过实际负载和故障演练确定。

仅凭心跳无法区分关机与网络分区。服务器也无法知道未接入守护的电脑是否正在使用同一雷神账号；用户需要了解覆盖范围。任何策略都不承诺所有断网/断电场景零误暂停或零时长消耗。

## 凭据与部署

服务器要在用户电脑关机后代发请求，就必须在明确授权后取得可用的雷神凭据。当前本地 DPAPI 密文不能直接交给服务器解密。应采用 HTTPS 传输、服务器加密存储、密钥与数据库分离、日志脱敏、用户撤销/删除、后台访问审计；不能把管理员能看统计理解成可以看到原始凭据。尚未验证雷神登录的异地/IP 限制、token 生命周期与服务器出口可用性，因此远程暂停不能提前宣称可用。

候选部署：现有官网保持在 Cloudflare；另设待确认的守护子域名承载 Web/API。香港服务器部署编译后的静态前端和独立 API/调度进程；持久化用户、设备、会话、授权、任务与审计数据。仅更新设备最后心跳和聚合状态，不把每 15 秒的全部原始心跳永久写库。前端在 CI 构建，服务器不运行开发服务器。

香港节点仅掌握用户描述的 2 核/1GB/30Mbps，未登录检查实际可用内存、磁盘、流量与现有服务；不能据此承诺用户容量。数据库选型和是否与下载服务共机，应在配置检查及负载验证后确定。下载带宽拥塞不能占满心跳/API资源，需要独立路由、连接限制与资源预算。

用户已选择 Tabler 统一两侧，品牌色沿用雷神守护的蓝色，浅色背景、清晰状态徽标、轻边框。用户端保留“我的守护、设备、记录、账号”四个入口，管理员采用“总览、用户、设备、任务、审计、系统健康”。以上候选表保留为选型记录；后续按 Tabler 开源版本实施，图表采用自托管的 Apache ECharts。当前完成三页视觉稿，不下载付费模板、不部署演示登录，也不把设计占位数值接入真实统计。

## 验收顺序

1. 本地修复：隔离窗口验证关机确认/取消、重复通知、请求超时与静默启动；真实 Windows 关机和账户暂停结果需单独核验，不在用户工作时触发关机。
2. 确认 Web 模板后做登录页、用户状态页、管理总览三个视觉稿，数据标注为示例。
3. 检查服务器与雷神接口可用性，实施认证、用户隔离、设备配对、持久化任务和最小后台。
4. 用测试账号覆盖多用户隔离、跨用户设备访问、同账号多设备、短暂断网、断电、关机取消、token 失效、服务器重启与网络分区，再开放可选远程兜底。
